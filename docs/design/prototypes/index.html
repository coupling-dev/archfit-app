Design notes

Who it suits

Small and medium product teams that write much of their code with coding agents. The buyer is the CTO or tech lead who owns the architecture.

Core bet

People cannot review every PR for architecture. So owners approve the intent once, agents repair what the gate blocks, and people spend attention only on decisions.

What gets easy

  • Seeing how much review the guardrails saved, as counts
  • Knowing what only you can decide
  • Onboarding without turning today's accidents into policy

What gets hard

  • The Overview reads many check runs from GitHub. Rate limits cap it
  • Agent attribution is a heuristic
  • Intent vs reality depends on the quality of docs and AI evidence

Data it needs

Exists today: policy, reports, checks, comments, agent_tasks, waivers, baseline, approvals on the exact commit. New: a decision index across repositories, the PR loop summary, and any history beyond what GitHub keeps.

Build cost

Medium. control/ui pages and forms, a decision index, and GitHub reads. The comment already carries agent_tasks. The two-reader layout is a gate/feedback change.

Risks and mitigations

  • Counts read as a score. Show events only, never a ratio
  • Agents loop on a task they cannot fix. The owner decision is marked as not for agents
  • Approval churn from agent pushes. Show which commit you approved and what changed since

Three failure classes

  • Architecture: a rule blocks. failure. Fix the code or get an owner decision
  • Evidence: the report is missing, stale, not comparable, or from an unknown engine. action_required. Never a verdict on the code
  • Subscription: action_required with subscription_suspended. Never a failure or a success

Rules this prototype keeps

  • Reports are customer-attested, never verified
  • The gate is success, failure, or action required
  • No publish button. Every change is a PR merged on GitHub
  • Approval is for the exact commit. A new push cancels it
  • An agent cannot clear an owner decision or authorize its own policy edit
  • The gate reads policy from the protected branch, never from the PR
  • Agent attribution and origin are triage only
  • Diagnostics and coupling seams never block. Only gate findings do
  • No score, no percentage, no "hours saved"
