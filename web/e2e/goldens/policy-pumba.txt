Custom rules and notes
no-container-to-chaos

Deny: pkg_container → pkg_chaos

Why: pkg/container is the domain model that chaos consumes. Importing chaos inverts the dependency and couples the model to every chaos action.

Instead: Move the shared type or value into pkg/container, and import it from pkg/chaos.

no-chaos-to-runtime

Deny: pkg_chaos → pkg_runtime

Why: Chaos says what to do through the container.Client interface; runtime adapters say how. A direct import bypasses the interface and ties chaos actions to one runtime.

Instead: Add the method to a container.Client sub-interface in pkg/container/client.go, and implement it in the runtime adapters.

no-util-to-domain

Deny: pkg_util → pkg_chaos

Why: pkg/util must stay domain-agnostic so any package can use it without pulling in chaos behavior.

Instead: Keep code that needs chaos types in pkg/chaos; give pkg/util functions plain values.
